## Implementation plan: log extraction and viewer migration

### Established baseline
`memory-api/crates/memory-api` is deleted. `log` must commit `memory_kernel = { git = "https://github.com/mankinskin/memory-kernel", branch = "main" }`; use a relative path only in a root development `[patch]`. Ticket `1b7e0c3d` proved patch-free remote resolution.

Create public crate `log` re-exporting internal `log-api`, with an empty default feature set. If a CLI, MCP, or HTTP binary is introduced during extraction, keep the names `log`, `log-mcp`, and `log-http` and implement those feature-gated bins on `transport-harness`. Keep log-domain typed manifest accessors in `log-api` extension traits with the exact existing `extra` keys; do not put log types into `memory-kernel`.

### Verified source surface
- API: `memory-api/crates/log-api`.
- Viewer and frontend: `memory-viewers/log-viewer`, including `frontend` and `e2e`.
- No separate `log-cli`, `log-mcp`, or `log-http` crate exists today. The viewer's internal MCP server is not evidence of a legacy standalone transport crate.

### Consumers to repoint
`memory-api/tools/cli/test-cli` and `memory-api/crates/memory-matrix` consume `log-api` outside the log package.

### Execution
1. Extract `log-api` behind public crate `log`; do not invent a legacy transport consolidation where no transport crate exists.
2. Move `log-viewer` with the log repository and preserve viewer API/MCP behavior.
3. Repoint `test-cli` and `memory-matrix` to the published log dependency, but first resolve the inverse edge: `log-api` consumes `test-api` while `test-cli` consumes `log-api`, so the consolidated test package must not create a `test <-> log` dependency cycle.
4. Extract after `test` is published and the transport-level cycle is removed.

### Acceptance criteria
```bash
cargo test -p log-api
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
cd memory-viewers/log-viewer/e2e && npm run test:managed
```
Validate the log viewer in an external fullscreen Chromium-family browser and capture Playwright screenshots. `AGENTS.md` mandates browser verification plus local-wrapper Playwright E2E.

### Risk
The test/log dependency pair blocks standalone proof until `test` is published and its legacy CLI-to-log import is structurally separated. `memory-kernel` must also resolve by remote git URL.
