## Objective

Implement embedded image extraction from PDFs: given a PDF, extract each embedded raster image to a file in an output directory. Sequenced last so it can be cut from v1 without blocking any other capability.

## Target Files

- `memory-api/crates/pdf-api/src/lib.rs` (or `src/images.rs` if split out) — implement the `ExtractImages` request variant body.
- `memory-api/crates/pdf-api/tests/` — tests using a fixture PDF containing at least one embedded raster image.
- `memory-api/crates/pdf/src/bin/pdf-cli.rs` — add the `extract-images` subcommand (already scaffolded as a placeholder in T6; fill in behavior here).
- `memory-api/crates/pdf/src/bin/pdf-mcp.rs` — add the `extract_images` named tool (already scaffolded as a placeholder in T7; fill in behavior here).

## Design

Implement using whatever crate T0 identified as covering image extraction (may be the same structural crate used for merge/split/metadata, e.g. `lopdf`'s embedded-XObject image stream access, or may require an additional crate — confirm against T0's final findings). If T0 concluded no adequate pure-Rust crate exists for this capability, this ticket's scope narrows to: implement the best-effort subset that is achievable (e.g. only the most common image encodings present in embedded PDF streams), explicitly documenting any image encoding left unsupported, rather than blocking the ticket entirely — the epic already treats this capability as cuttable/best-effort-last.

Each extracted image is written to the request's `output_dir` (an explicit path, subject to T2's root confinement) with a deterministic filename (e.g. `<original-stem>-image-<n>.<ext>`, extension matching the detected image encoding). Extraction does not overwrite the source PDF; it only writes new files into `output_dir`, so the copy-on-write semantics here are: reject if any target image filename already exists in `output_dir` unless `overwrite: true`.

## Acceptance Criteria

- [ ] `ExtractImages` extracts at least one embedded image from a fixture PDF known to contain an embedded raster image, writing it to the requested output directory with a deterministic filename.
- [ ] Extracted image files are valid, openable images in their claimed format (not corrupted byte dumps).
- [ ] `ExtractImages` on a PDF with no embedded images returns success with zero extracted files, not an error.
- [ ] `ExtractImages` refuses to overwrite an existing output filename in `output_dir` unless `overwrite: true`, consistent with T2's write-safety contract.
- [ ] Any image encoding explicitly unsupported by the T0-selected crate(s) is documented in this ticket's description (updated during implementation) rather than causing a silent empty/wrong result.
- [ ] `pdf-cli extract-images` and the `pdf-mcp` `extract_images` tool both invoke this implementation and are covered by at least one manual invocation against a fixture.
- [ ] `cargo test -p pdf-api` passes including the new image-extraction tests.
- [ ] This ticket has no dependent tickets in the `depends_on` graph (confirmed via `mcp_ticket-mcp_list_edges` after creation).
