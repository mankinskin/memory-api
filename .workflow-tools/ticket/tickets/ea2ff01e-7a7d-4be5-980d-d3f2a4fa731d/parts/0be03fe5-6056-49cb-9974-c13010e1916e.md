## Objective

Implement PDF creation in two modes: (a) a programmatic primitive using a pure-Rust PDF-generation crate (candidate: `printpdf`, to be confirmed by T0), and (b) an optional path that shells out to `typst-cli` when detected on PATH, producing PDF output directly from a typst source document, degrading gracefully with a clear error when `typst-cli` is not installed.

## Target Files

- `memory-api/crates/pdf-api/src/lib.rs` (or `src/create.rs` if split out) — implement `CreateProgrammatic` and `CreateFromTypst` request variant bodies.
- `memory-api/crates/pdf-api/tests/` — tests for both creation paths.

## Design

**Programmatic primitive (`CreateProgrammatic`)**: Accepts a minimal, crate-agnostic `PdfCreateSpec` (finalized once T0/T2 settle on the crate — expected to support at minimum: page size, and a list of text blocks with position and font size; image embedding in a created document is out of scope for this ticket — that is a separate concern from T9's image *extraction*). Produces a new PDF at the request's `output` path, subject to T2's copy-on-write/`overwrite` enforcement and sandboxing.

**Typst path (`CreateFromTypst`)**: Accepts a `source` path (a `.typst` file, itself subject to root confinement) and an `output` path. Detection: at request time, check whether `typst-cli` (or `typst`, depending on what the actual installed binary is named — confirm during implementation) is resolvable on `PATH` (e.g. via `which`/`Command::new("typst").arg("--version")` probe). If not found, return a `PdfError` variant (e.g. `PdfError::TypstNotFound`) with a clear, actionable message — do not panic, do not silently fall back to the programmatic primitive. If found, shell out via `std::process::Command` to compile the typst source to the requested output path, propagating typst's own error output into the `PdfError` on non-zero exit.

`typst-cli` must NOT be added as a `[dependencies]` or `[build-dependencies]` entry in `Cargo.toml` — it is a runtime-only, optional external tool. This must be explicit in code comments and in this ticket's validation.

## Acceptance Criteria

- [ ] `CreateProgrammatic` produces a valid, openable PDF file containing the requested text content at the requested page size.
- [ ] `CreateProgrammatic` respects T2's copy-on-write/`overwrite` enforcement (refuses to clobber an existing output path without `overwrite: true`).
- [ ] `CreateFromTypst` detects `typst-cli` presence/absence on `PATH` at request time (not at build time).
- [ ] `CreateFromTypst` returns a clear, actionable `PdfError` (not a panic, not a generic I/O error) when `typst-cli` is absent.
- [ ] `CreateFromTypst` produces a valid output PDF when `typst-cli` is present and given valid typst source (test may be conditionally skipped in CI environments lacking `typst-cli`, but the skip must be explicit and logged, not silent).
- [ ] `typst-cli`/`typst` does not appear in `memory-api/crates/pdf-api/Cargo.toml` `[dependencies]` or `[build-dependencies]`.
- [ ] `cargo test -p pdf-api` passes (with the typst-present test conditionally skipped where `typst-cli` is unavailable).
