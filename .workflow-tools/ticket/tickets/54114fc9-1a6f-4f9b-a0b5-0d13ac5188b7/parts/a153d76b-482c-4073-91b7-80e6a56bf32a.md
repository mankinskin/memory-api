## Scope decisions (interview-resolved, 2026-07-31)

**Positioning.** Rescoped from a standalone spec into the umbrella architecture spec that the following overlapping open tickets slot into as implementation/consumer work: f35f4dd9 (persisted step graph — now a hard dependency, see above), 79c4ac3e (delegation-cost epic), 46d8b25d (gate placement), 1fbf2d84 (Iteration Agent review→interview→commit→handoff sequencing — direct conceptual overlap), 6bebc161 (sandbox orchestration track), fe221c20 (orchestrator round-trip fixture tests). The spec must name each of these and state how it slots in, not draft in isolation.

**Drive vs. gate.** The spec itself documents dependencies and acceptance criteria only — it does not drive execution. The controller it specifies is gate/sequence only: it enforces the decision logic (state transitions, retry-limit escalation, write-and-die termination) deterministically, reusing existing enforcement primitives (ticket-api lifecycle.rs SchemaRegistry, enforce_dependency_progress, WorkflowModel frontier). It does not itself spawn or terminate agent sessions — actual dispatch mechanics are out of scope for this spec and belong to separate implementation tickets, including the already-ticketed agent-harness track (component `agent-harness`, ~19 open tickets, architecture in DESIGN_AGENT_HARNESS.md: agent-shared/agent-core/agent-server/agent-uapi) if/when that stack is built.

**State vocabulary.** Reuse the existing `SessionWorkflowNodeStatus` (Pending/InProgress/Blocked/Done/Deferred) from memory-api/crates/session-api/src/model/workflow.rs directly. Do not introduce a second, parallel Planning/Executing/Testing/Reviewing/Escalated enum — express controller phases as behavior over the existing five statuses.

**Crate boundary.** The controller is a standalone crate (new, or hosted in session-api/ticket-api) usable today by ticket-mcp/session-mcp, independent of and not blocked on the agent-harness track. When agent-harness's agent-core is eventually built, it depends on this crate rather than owning the logic itself.

**Related, split out:** the index-staleness defect originally assumed by this ticket's framing was not reproduced by research (scan_helpers.rs::entry_is_current correctly detects mismatches; regression suite passes). It is tracked separately — see the new investigation ticket linked below and existing ticket 1d6a033e — and this spec must NOT assume that root cause.
