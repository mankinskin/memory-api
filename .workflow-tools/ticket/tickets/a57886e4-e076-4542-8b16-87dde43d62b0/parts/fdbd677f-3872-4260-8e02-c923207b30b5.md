## Implementation plan: doc extraction and viewer migration

### Established baseline
`memory-api/crates/memory-api` is deleted. `doc` commits `memory_kernel = { git = "https://github.com/mankinskin/memory-kernel", branch = "main" }`; a relative path is allowed only in a root `[patch]` development override (ticket `1b7e0c3d` proved patch-free remote resolution).

Create public crate `doc` re-exporting `doc-api`, with empty defaults and a feature-gated `doc-http` bin built on `transport-harness` from `memory-kernel`. The ticket pilot (`26da8f59`) establishes the single-crate shape. Keep document-domain typed manifest accessors, if present, as `doc-api` extension traits preserving existing `extra` keys; do not put doc types in the kernel.

### Verified source surface
- API: `memory-api/crates/doc-api`.
- Legacy transport to consolidate first: `memory-api/tools/http/doc-http`.
- Viewer and frontend: `memory-viewers/doc-viewer`, including `frontend` and `e2e`.
- No `doc-cli` or `doc-mcp` crate is known to exist today.

### Open scope question (resolve during planning, not blocking creation)
Confirm whether a standalone `doc-cli`/`doc-mcp` genuinely does not exist (i.e. doc is HTTP + viewer only, like the `log` precedent where no separate `log-cli`/`log-mcp`/`log-http` crate exists), or whether cli/mcp access to doc is only exposed indirectly (e.g. via `doc-viewer`'s internal MCP server, or via another tool). If no cli/mcp transport exists, the extracted `doc` crate should expose only the `doc` lib, the `doc-http` bin, and the viewer — do not fabricate cli/mcp bins with no legacy source.

### Consumers to repoint
Only `memory-api/tools/http/doc-http` currently consumes `doc-api`; the viewer uses the doc HTTP surface rather than a direct API dependency. Any other crate consuming `doc-api` outside doc's own transports/viewer must be identified and repointed before legacy in-tree paths are deleted.

### Execution
1. Resolve the open scope question above (cli/mcp existence) before finalizing the transport bin list.
2. Fold `doc-http` (and any confirmed cli/mcp transport) into feature-gated bins in public crate `doc`, preserving routes, binary names, and integration tests.
3. Move `doc-api`, public crate `doc`, and `doc-viewer` into the standalone doc repository, preserving the viewer-to-HTTP boundary.
4. Repoint root membership and deploy/install configuration; remove the monorepo paths only after the viewer and HTTP transport compile externally.

### Acceptance criteria
```bash
cargo test -p doc-api -p doc-http
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
cd memory-viewers/doc-viewer/e2e && npm test
```
Validate the doc viewer in an external fullscreen Chromium-family browser and capture Playwright screenshots. `AGENTS.md` requires browser verification plus the local Playwright wrapper E2E.

### Risk
Standalone proof depends on the published `memory-kernel` git dependency. The viewer must not retain an accidental monorepo path dependency after relocation, and the cli/mcp scope question must not be left unresolved into implementation.
