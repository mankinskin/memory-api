## Objective

Wire the `pdf-cli` binary transport using `transport-harness`, exposing every `pdf-api` operation as a CLI subcommand.

## Target Files

- `memory-api/crates/pdf/src/bin/pdf-cli.rs`
- `memory-api/crates/pdf/Cargo.toml` (confirm `cli` feature deps are correct; no new deps expected beyond what T1 set up)

## Design

Follow `transport-harness`'s CLI scaffolding pattern (consult `memory-kernel/crates/transport-harness` and its spec at `memory-kernel/.spec/specs/e5294ae5-6bff-44dc-81a9-24a44615b775/spec.toml` for the canonical harness contract — this ticket wires `pdf-api::execute` behind that harness's CLI conventions, it does not redefine them). One subcommand per `PdfRequest` variant from T2 (extract-text, extract-images, merge, split, reorder-pages, delete-pages, read-metadata, write-metadata, create, create-from-typst), each mapping CLI args to the corresponding `PdfRequest` variant and printing the `PdfResponse` (or error) to stdout/stderr per the harness's existing output conventions (JSON and/or TOON, matching how other CLI transports in this repo format output — check `peek-cli` or `fs-cli` if present for the established pattern).

The confinement `root` parameter required by `pdf_api::execute` must be surfaced as a required CLI flag (e.g. `--root <path>`), not defaulted to `.` or omitted — every invocation must make the allowlist root explicit.

## Acceptance Criteria

- [ ] `pdf-cli` has one subcommand per `pdf-api` operation (text extraction, image extraction, merge, split, reorder, delete, read-metadata, write-metadata, create-programmatic, create-from-typst).
- [ ] Every subcommand requires an explicit `--root` flag and rejects invocation without it.
- [ ] Every output-producing subcommand exposes an explicit `--output` argument and an `--overwrite` flag, matching T2's write-safety contract (no silent overwrite without the flag).
- [ ] Running `pdf-cli extract-text --root <dir> <fixture.pdf>` against a T3 test fixture prints the expected extracted text.
- [ ] Running any subcommand with a path outside `--root` produces a clear CLI error, not a panic or stack trace.
- [ ] `cargo build -p pdf --features cli` succeeds and produces a working `pdf-cli` binary.
